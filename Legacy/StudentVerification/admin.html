How the Database Works

The Student Verification service runs on port 3020 and uses an embedded SQLite database stored as a file called students.db in the project folder.

On first run: the DB file doesn't exist yet, so the service creates a fresh SQLite database in memory, sets up the students table, and seeds it with 8 sample records. It then writes this to students.db.

On subsequent runs: the service reads students.db from disk and loads it. All previous records are preserved. Any students you add/delete here are saved back to the file immediately.

Verification flow: The concession frontend POSTs {identification_number, school, date_of_birth} to /verify. The service checks all three fields against the DB. If matched → verified: true. If not → verified: false with a reason.
